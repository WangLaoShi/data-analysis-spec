# 优化建议输出规则（Spec 5.10）

把问题结论转成可执行行动，而不是口号。

**模板：** `docs/templates/08-recommendation-cards.md`。

## 合格标准（每条都必须满足）

- **可落地**：有明确动作对象与场景  
- **可执行**：有步骤或负责人角色假设  
- **可量化**：有预期指标/幅度/观察窗口（或明确「待定基线需补数」）  
- **有对应**：能指回前面的问题结论或数据发现  

## 禁止的空泛话术（示例）

- 「加强运营」「提升意识」「优化体验」「持续关注」「多管齐下」——若无具体动作与指标，一律重写。

## 工作流程

1. 列出问题结论清单。  
2. 逐条设计建议：动作 → 影响指标 → 预期变化 → 验证方式 → 风险。  
3. 按影响 × 可行性排优先级。  
4. 无法量化时，写清缺什么数据才能量化，而不是编数字。

## 输出

```markdown
## 建议列表（按优先级）
| ID | 对应问题 | 动作 | 责任角色 | 影响指标 | 预期量化 | 验证窗口 | 风险 |

## 建议详述
### R1 …
```

## 原则

- 无对应问题的建议不输出。  
- 建议与结论、图表中的数字口径一致。
